# 배너 및 단말 관리

모바일 서브메인 빌보드 · 단말 목록 상단 배너 · 단말 출시 관리를 팀원들과 함께 기록하는 내부 도구입니다.
빌드 과정이나 서버 코드 없이 `index.html` 파일 하나로 동작하며, 데이터는 [Supabase](https://supabase.com)에
저장되어 여러 사람이 같은 화면을 실시간으로 공유합니다.

## 처음 설정하기 (한 번만 하면 됩니다)

### 1. Supabase 프로젝트 만들기

1. [supabase.com](https://supabase.com) 에서 무료로 가입하고 새 프로젝트를 만듭니다 (리전은 아무 곳이나, DB 비밀번호는 아무거나 — 이후 직접 쓸 일 없습니다).
2. 프로젝트가 만들어지면 왼쪽 메뉴 **SQL Editor**로 들어가서 이 저장소의 [`supabase/setup.sql`](./supabase/setup.sql) 파일 내용을 전체 복사해 붙여넣고 실행합니다.
   - 테이블 생성, 접근 권한 설정, 실시간 동기화 활성화가 한 번에 됩니다.
3. 왼쪽 메뉴 **Settings → API**로 들어가서 다음 두 값을 복사해 둡니다.
   - **Project URL** (예: `https://xxxxxxxx.supabase.co`)
   - **anon public** 키 (긴 문자열)

### 2. 이 값들을 `index.html`에 채워 넣기

`index.html` 파일에서 아래 두 줄을 찾아 방금 복사한 값으로 바꿉니다 (`Ctrl+F`로 `SUPABASE_URL` 검색).

```js
var SUPABASE_URL = "YOUR_SUPABASE_PROJECT_URL";
var SUPABASE_ANON_KEY = "YOUR_SUPABASE_ANON_KEY";
```

GitHub 웹 화면에서 파일을 열어 연필(✎) 아이콘으로 바로 수정하고 커밋해도 되고, 로컬에서 고친 뒤 push해도 됩니다.

> anon key는 "비밀 키"가 아닙니다 — Supabase는 이 키가 브라우저 코드에 그대로 노출되는 것을 전제로 설계되어 있고,
> 실제 접근 제어는 위 SQL이 설정한 정책(RLS)이 담당합니다. 그대로 공개 저장소에 커밋해도 괜찮습니다.

### 3. GitHub Pages로 배포하기

저장소 **Settings → Pages**에서 Source를 `main` 브랜치(폴더는 이 폴더를 저장소 루트로 두었다면 `/(root)`)로 지정하면,
몇 분 뒤 `https://<계정명>.github.io/<저장소명>/` 주소로 팀원들과 공유할 수 있는 링크가 생깁니다.

## 알아두면 좋은 점

- **동시 편집**: 저장은 "전체 데이터 한 덩어리"를 통째로 덮어쓰는 방식입니다. 두 사람이 정확히 같은 순간에
  저장하면 나중에 저장한 쪽이 이길 수 있습니다 — 평소처럼 가끔씩 기록하는 용도로는 문제없지만, 초 단위로
  동시에 편집하는 상황은 염두에 두지 않았습니다.
- **접근 제어**: 링크와 Supabase anon key를 아는 사람은 누구나 데이터를 읽고 쓸 수 있습니다 (로그인 기능 없음).
  더 강한 통제가 필요하면 Supabase Auth를 붙여 RLS 정책을 사용자별로 좁히는 방향으로 확장할 수 있습니다.
- **백업**: 상단의 "내보내기" 버튼으로 언제든 현재 데이터를 JSON 파일로 내려받을 수 있습니다. "가져오기"는
  파일 내용으로 팀 전체의 공유 데이터를 덮어쓰므로 실행 전 확인 창이 뜹니다.
